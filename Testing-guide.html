JustHumanResource Testing Guide

End-to-end tester walkthrough for validating the JustHumanResource application as a whole, including setup, employee lifecycle, payroll, leave, KPI, recruitment, requests, finance, reports, mobile views, and access control.

Format: HTML Application: JustHumanResource Stack: Spring Boot, Thymeleaf, Flowable, Keycloak Last updated: 2026-08-26

How To Use This Guide

  1. Run tests in the same logical order as the guide, because later flows depend on earlier setup data.
  2. Record evidence for every major step: screenshot, created record number, downloaded file, email result, or API response.
  3. Retest failed items after fixes using the same user role and the same data condition.
  4. Use a clean test company, test employees, and test payroll periods. Do not run finance/payment tests against real payroll data.

Pre-Test Environment Checklist

[ ]Application is running and the tester can reach the base URL, login page, and Swagger/OpenAPI page if enabled.
[ ]PostgreSQL database is connected and contains a test company context.
[ ]Keycloak/OIDC login works for each tester role, and logout returns the user to a non-authenticated state.
[ ]Flowable process definitions are deployed: onboarding, leave approval, payroll approval, payroll close, recruitment, KPI, and generic requests.
[ ]Email provider settings are either valid for testing or intentionally stubbed, with expected behavior documented.
[ ]Payment gateway/webhook settings are test-mode only.
[ ]Fixed Asset Management integration is configured or the local asset catalog fallback is populated.
[ ]Browser matrix is defined. At minimum test current Chrome/Edge desktop and a mobile viewport.

Full End-To-End Walkthrough

This is the recommended happy-path order for walking through the whole application.

  1. Login as Admin and confirm users, groups, roles, enable/disable, and password reset actions.
  2. Login as HR and create core organization data: departments, job grades, job steps, pay groups, PAYE bands, pension schemes, and payroll pay items.
  3. Create or onboard employees, attach job/payroll data, upload documents, and assign employee-specific pay items.
  4. Login as Employee and validate profile, bank information, documents, payroll view, leave request, KPI view, and generic request creation.
  5. Login as Manager/Approver and approve, reject, or return employee leave and generic requests.
  6. Run KPI setup, assignment, measurement upload/manual entry, appraisal start, self-review, manager review, and reports.
  7. Run recruitment from job opening to candidate application, interview, offer, approval, and candidate onboarding.
  8. Run payroll from setup to calculation, review, payslip generation, approval, reports, payment/posting, and period close.
  9. Login as Finance Officer and validate lock approval, closed periods, bank details, journals, and posting exports.
  10. Validate mobile employee screens and biometric wrapper expectations if testing the packaged mobile build.
  11. Repeat key screens with restricted roles to confirm records and actions are hidden where required.

[ ]Delete only a throwaway test user and verify it is removed from the list and identity provider.

4. Employee Lifecycle

Primary screens: /employees, /employee/dashboard, /employee/profile, /employee/documents.

  1. As HR, create an employee/onboarding record with department, job step, pay group, line manager, email, TIN/RSA/PFA, and bank details.
  2. Confirm duplicate email validation blocks duplicate work or personal email values.
  3. Upload an employee CSV using the supplied employee template and confirm valid rows are imported and invalid rows return readable errors.
  4. Open the employee record, update personal, job, pay group, and bank information. Confirm position history updates where applicable.
  5. Upload employee documents, view, download, and delete a test document.
  6. Assign employee-specific allowances, deductions, and tax reliefs. Confirm they appear in payroll pay item views.
  7. Suspend an employee for a date range and confirm payroll excludes the employee where the period overlaps the suspension.
  8. Unsuspend the employee and confirm the employee returns to active payroll eligibility.
  9. Toggle restricted visibility and verify Restricted HR and Job HR users see only permitted employee records.
Evidence to capture: employee ID, onboarding/workflow status, uploaded document name, pay item assignment, and visibility result for restricted roles.

[ ]Enable and disable the custom path and confirm only enabled paths are selectable.
[ ]Assign a request type to line-manager routing and confirm the employee's manager receives the task.
[ ]Assign a request type to custom routing and confirm each configured approver receives the task in sequence.
[ ]Confirm returned requests can be corrected and resubmitted without losing comments/attachments.

9. KPI And Appraisal Flow

Primary screens: /kpi, /kpi-report/dashboard, /kpi-report/scorecard, and employee KPI screens.

  1. Create KPI definitions with code/name, category, unit, target, weight, and scoring details.
  2. Assign KPIs by employee, department, and job step. Confirm assignment totals respect maximum KPI weight.
  3. Record KPI measurements manually for a selected period and confirm score calculations update.
  4. Download the KPI CSV template, upload valid and invalid measurement files, and verify row-level import feedback.
  5. Start an appraisal cycle for an employee and confirm Flowable tasks are generated.
  6. Login as Employee and complete self-review from the employee KPI/performance screen.
  7. Login as Manager and complete manager review/finalize appraisal.
  8. Review KPI dashboard, scorecard, department report, top performers, appraisal summary, and employee scorecard.
  9. Validate quarterly and monthly orchestrator behavior if scheduled process testing is in scope.

11. Payroll Setup And Processing

Primary screens: /payroll, payroll fragments/tabs, /payroll/historical-adjustments, and payroll reports.

  1. Create allowances, deductions, and tax reliefs. Include taxable allowance and statutory deduction cases.
  2. Update pay items and verify inactive/deleted items no longer apply to future payroll calculations.
  3. Assign pay items to pay groups with effective dates and confirm removed items are deactivated, not duplicated.
  4. Assign pay items directly to an employee and confirm employee-level overrides are reflected.
  5. Create or identify the current payroll period and confirm status before processing.
  6. Run payroll processing for the current period and confirm employee runs are generated.
  7. Inspect payroll run calculations: gross salary, allowances, taxable income, PAYE, pension, deductions, net pay, and employer pension where shown.
  8. Approve/post payroll through the configured payroll approval workflow.
  9. Generate payslips, view current payslips, and verify employee self-service can see only their own payslip.
  10. Email current and past payslips, confirming success or configured email failure behavior.
  11. Close/lock the payroll period and confirm no blocked employee creation or payroll changes can affect the closed period.
  12. Create a historical payroll adjustment for a closed period and verify versioned correction/audit behavior.
Do not test real payment disbursement in a shared environment. Use a payment sandbox and capture only test transaction references.

15. Mobile Employee Experience

Primary routes: /mobile/employee/dashboard, /mobile/employee/performance, /mobile/employee/payroll, /mobile/employee/profile, plus mobile leave/documents where enabled.

  1. Open the mobile routes in a phone-sized viewport and confirm bottom navigation highlights the current screen.
  2. Validate mobile dashboard data matches desktop employee dashboard data.
  3. Validate mobile KPI, payroll, and profile screens show only the logged-in employee data.
  4. Open the static wrapper at /hr-mobile-v1/index.html if testing the packaged mobile app shell.
  5. For biometric testing, confirm first login uses normal OIDC login, later launches use biometric prompt plus refresh-token flow, and expired refresh falls back to login.
  6. Rotate viewport/device orientation and confirm layout remains readable with no clipped critical actions.

16. Audit, Logs, Errors, And Security Regression

[ ]Create, update, and delete representative records and confirm audit log/access log entries are created where expected.
[ ]Trigger validation errors on forms and APIs and confirm messages are understandable and do not expose stack traces.
[ ]Open a non-existent page and a forced server-error scenario if available. Confirm branded error pages appear.
[ ]Attempt direct object access: employee A trying to download employee B documents, payslips, requests, or attachments.
[ ]Verify CSRF/session behavior for form posts and logout.
[ ]Confirm restricted HR and Job HR scoping applies consistently across employee list, payroll, reports, documents, and APIs.
